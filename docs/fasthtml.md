# Migration Plan: Flask to FastHTML

This document outlines the strategy for migrating the `smart-investor` application from a traditional Flask backend + Vanilla JS/HTML frontend to a pure Python stack using **FastHTML** and **HTMX**.

## 1. Architectural Shift

*   **Current State:** Flask serves a static `index.html`. Vanilla JS intercepts the form submission, makes a `fetch` request to a JSON API endpoint (`/analyze`), and manually updates the DOM with the results.
*   **Target State:** FastHTML replaces both Flask and the Vanilla JS. The entire UI is built using Python components. Form submissions are handled by HTMX, which directly swaps the resulting HTML generated by the Python backend into the DOM.

## 2. Dependency Management

1.  **Remove:** `flask`, `werkzeug`, `jinja2` (and related Flask dependencies).
2.  **Add:** `python-fasthtml` (which includes Starlette, Uvicorn, and HTMX integrations).
3.  **Update:** Update `pyproject.toml` and `requirements.txt` to reflect these changes.

## 3. Frontend Redesign (Pythonic UI)

The massive `templates/index.html` file will be completely removed. Instead, the UI will be constructed in Python using FastHTML components (e.g., `Div`, `Form`, `Input`, `Textarea`, `Button`).

### Key UI Features to Translate:
*   **Tailwind CSS:** We will include the Tailwind CDN script in the FastHTML `head` configuration.
*   **Custom Fonts & Styles:** The Google Fonts and custom CSS animations (from `static/style.css`) will be injected into the FastHTML `Headers`.
*   **Dynamic Language & Placeholders:** Instead of JS event listeners, we can use HTMX to re-render the form or specific inputs when the language radio button changes (using `hx-get` on the radio buttons), or keep a tiny bit of hyperscript/Alpine.js for purely client-side state like placeholder toggling.
*   **Markdown Rendering:** Instead of `marked.js` on the frontend, we will use a Python markdown library (like `markdown` or `mistune`) on the backend to convert the agent responses to HTML *before* sending them to the browser via HTMX.

## 4. Backend Redesign (Routing & HTMX)

The Flask app (`app.py`) will be replaced by a FastHTML app (e.g., `main.py`).

### Route 1: `GET /`
*   Returns the main layout: Header, the Input Form, and an empty `#results` container.
*   The `<form>` will be configured with HTMX attributes:
    *   `hx-post="/analyze"`
    *   `hx-target="#results"`
    *   `hx-swap="innerHTML"`
    *   `hx-indicator="#spinner"` (to show the loading state automatically).

### Route 2: `POST /analyze`
*   Receives the form data (Idea, API Key, Provider, Language).
*   Executes the existing asynchronous agent logic (Market, Financial, Competitive, Synthesizer).
*   **Crucial Change:** Instead of returning a JSON dictionary, this route will construct and return the HTML components for the 4 result cards directly. HTMX will take this HTML and inject it into the `#results` div.

## 5. Agent Logic Preservation

The core engine in the `agents/` directory (**MarketLogicAgent**, **FinancialAgent**, **CompetitiveAgent**, **SynthesizerAgent**) will remain **100% untouched**. 
*   They are already written using `asyncio`, which is perfectly compatible with FastHTML's underlying ASGI framework (Starlette).
*   The parallel execution `await asyncio.gather(...)` will continue to function exactly as it does now.

## 6. Advanced Enhancement: Real-time Streaming (Optional)

Because FastHTML has built-in support for Server-Sent Events (SSE) and WebSockets, we could enhance the user experience by streaming the results as they finish, rather than waiting for all 4 agents to complete.
*   *Phase 1:* Simple HTMX POST (waits for all agents, then returns all HTML).
*   *Phase 2:* Use SSE. As each agent finishes, the backend yields an HTMX OOB (Out-of-Band) swap to update that specific card (e.g., updating `#market-result` while `#financial-result` is still loading).

## 7. Deployment Considerations

*   The execution command changes from `uv run python app.py` (Flask) to `uvicorn main:app --host 0.0.0.0 --port 5000` (FastHTML).
*   Deployment platforms like Render, DigitalOcean, or Railway will simply need their start commands updated to use Uvicorn.
